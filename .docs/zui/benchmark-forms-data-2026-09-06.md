# 表单、日期、复杂输入与编辑器能力对标

核查日期：2026-09-06。ZUI 基线为 `07778ba` 工作区，覆盖当前 27 个 input 文档家族、Form/Field 基础设施、集合与文件运行时。只做源码和官方资料研究，不代表当前 CI 或所有浏览器行为已通过。

本次官方页面显示 Mantine **9.6.0**、Ant Design **6.6.2**；React Aria 使用当前官网 Components 文档，不把旧 React Spectrum 组件目录当成 React Aria 的目录。版本仅用于本次能力快照，下一轮锁依赖时重新确认兼容版本。目录证据：[Mantine core](https://mantine.dev/core/package/)、[Mantine dates](https://mantine.dev/dates/getting-started/)、[Ant Design overview](https://ant.design/components/overview/)、[React Aria DatePicker 页的完整侧栏](https://react-aria.adobe.com/DatePicker)。

## 1. 结论与口径

现有 27 个家族已经具备真实交互基础，主要差距不是按钮尺寸或再补几个别名，而是：**Form 值管理与动态数组、日期/时间/周期选择、集合搜索与级联多选、上传高级生命周期，以及可编辑文档**。这些应进入正式能力范围；旧文档里“不做范围滑块/编辑器/field array”等阶段性限制不再作为排除依据。

状态定义：**覆盖**表示已有该类核心能力的公开 API 和实现；**部分**表示已有基础但缺少列出的成熟能力；**缺失**表示当前没有对应能力合同，原生 HTML 的可组合性不算成已完成的成品组件；**需重构**表示现有值形状或所有权无法直接承载目标能力。所有状态都是源码/接口层对照，不等于视觉、性能、可访问性验收结论。

下文的“目标 API”均为**下一轮设计目标，尚未实现**。可以合并成组件模式、compound 部件或可选入口，但不能因为合并名字而删掉能力。React 库用于核对能力与责任划分，不引入 React wrapper，也不照搬其 hook、私有值仓库或样式 DSL。

| S03 | 远程分页与创建值              | 部分     | options/source 互斥、query、loading/error/retry、cursor/loadMore、getKey/getLabel、retainSelected、allowCreate/onCreate；复用现有 AsyncCollectionQuery latest-wins/AbortSignal，补分页适配，不内建另一个全局缓存。[React Aria ComboBox](https://react-aria.adobe.com/ComboBox)                                                                                                |
| S04 | 搜索/多选便利模式             | 部分     | searchable、inputValue、maxSelected、selectAll/filterScope、empty/loading/error、clear、tag overflow、selection commit；保留 options 和 compound 两种入口，不能要求简单需求手写二十个部件。                                                                                                                                                                                   |
| S05 | Transfer table/tree/远程 pane | 部分     | 受控 source/target 临时选择、renderPane 或有限 table/tree adapters、分页/搜索状态、disabled 策略、move callbacks；底层 key identity 与 FormData 不变。                                                                                                                                                                                                                        |

当前远程基础实际是 [AsyncCollectionQuery](../../ui/zui/src/runtime/collection/async-query.ts)，已有取消和 generation，不拥有缓存、options 或选中值。目标不是把“远程数据”重复记成全缺失，而是为多个真实选择控件提供一致、可组合的消费合同。Ant Cascader 的 lazy/search 以及 TreeSelect 的父子选择规则也有明确限制，必须逐条形成 ZUI 自己的合同，不能只复制属性名。

## 4. Form 基础设施：先补值所有权，再做复杂表单

官方对照：Mantine 提供 values、字段读写、初始化、数组操作和 dirty/touched；Ant Form 提供受控字段域、Form.List、依赖与验证；React Aria Form 保留原生表单语义和校验关系。这些实现路径不同，ZUI 应保留 native FormData 基线，并增加明确的 model 模式，而不是让 DOM 与隐藏 store 互相猜值。[Mantine useForm](https://mantine.dev/form/use-form/)、[Mantine nested fields](https://mantine.dev/form/nested/)、[Ant Form](https://ant.design/components/form/)、[React Aria Form](https://react-aria.adobe.com/Form)。

| ID  | 能力                          | 现有覆盖                                 | 目标 API/重构点                                                                                                                                                                                         |
| --- | ----------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F01 | native/model 值模式           | 当前 native + validated output           | `valueMode="native"` / `valueMode="model"`；model 支持 `values/defaultValues/onValuesChange`，外部受控值更新不重复触发用户 change。Field 的 control adapter 负责读写，不能直接 set DOM value 绕过控件。 |
| F02 | 字段值与初始化                | controller 目前只读字段状态/写错误       | `getValues/getFieldValue/setValues/setFieldValue/resetField/initialize`；初始化是否覆盖 dirty 字段显式，批量写原子提交；reset baseline 与 defaultValues 分开定义。                                      |
| F03 | 动态 FieldArray               | typed path 已有，数组管理缺失            | `ZFormList path` 或 `controller.fieldArray(path)`，提供 insert/remove/move/replace 与稳定 row id；索引改变时迁移 touched/errors/dependency，不让 DOM key=数组索引。                                     |
| F04 | watch/依赖/局部重算           | subscribeField 只观察状态                | `subscribeValue(path, listener)`、依赖变更闭包、批量通知；observe 与用户 change 回调分开，不能导致受控回路。                                                                                            |
| F05 | 字段验证/异步规则             | Standard Schema 全量 parse +局部消息更新 | schema 仍是基础；增加有限 callable field validator/可选 field-schema adapter，AbortSignal、触发策略、debounce、交叉字段 context、过期结果丢弃。Standard Schema 本身不能保证只 parse 一个字段。          |
| F06 | server errors 与状态          | setErrors、field status 已有             | 增补 clearFieldError/clearErrors、错误 summary、聚焦真实控件、pending submit、防重复提交、提交 Promise 生命周期。保留 onValidSubmit/onInvalidSubmit 原有数据与原生事件。                                |
| F07 | 条件字段和 preserve           | mounted registry 已有                    | `preserve`、disabled/hidden/unmounted 提交策略、注册/反注册和 model 保留值；必须区分 validated model 与原生 FormData 的 successful controls。                                                           |
| F08 | Form layout/Fieldset/分步表单 | 基础Field布局与Form大小已有              | label布局、required标记、compact/help/feedback、error summary；多步表单复用 Form model + Stepper/Disclosure，支持只验证本步和回退保值。                                                                 |
| F09 | 非标控件/编辑器适配           | FormValueBridge 可提交标量/数组          | 公开最小 control adapter：value/get/set/reset/focus/serialize；RichText、CodeEditor、Upload 和 range 不再各自伪造隐藏输入逻辑。                                                                         |

先落实 F01/F02/F03 的值与身份设计，再把 DateTime、树多选和编辑器接入。不要先给每个新组件加独立 reset、dirty、watch 和 validation store。

## 7. 每个新能力必须带齐的 API 维度

1. **值与事件**：value/default/bindable、空值、草稿与已提交值、外部写入与用户事件边界；原生 oninput/onchange 保留，结束交互才需要的 onValueCommit 不强塞给所有组件。
2. **表单与校验**：name/form/required/disabled/readonly、FormData编码、reset baseline、Field关联、client/server/async error、focus target；范围/集合/文件/编辑器的值形状有明确codec。
3. **数据来源**：静态options、受控options、异步query、error/retry/loadMore、AbortSignal和过期结果、孤儿选中值、对象key；虚拟化不能丢键盘/ARIA目标。
4. **交互**：keyboard、IME、paste、pointer/touch、focus restore、RTL、locale、屏幕阅读器；格式化不能破坏光标和composition。
5. **视觉与偏好**：沿用五档control、独立indicator/内容尺寸、Field校验状态与语义色、dark/high contrast/reduced motion；ColorPicker的业务色不等于组件tone。
6. **生命周期**：请求、timer、observer、object URL、editor/worker有唯一owner；controlled更新、reset、卸载、重挂载和HMR都有验收案例。
7. **简单与高级入口**：常见需求提供简短成品API；特殊需求保留compound/adapter/原生依赖扩展。类型区分互斥模式，不能接受参数后静默忽略。

## 9. 删减、重命名、拆合与重新组合

建议交付顺序是“先确认责任与能力承接表 → 合并/下沉实现 → 迁移成品入口 → 删除旧别名/无效路径 → 补新增能力”，并和第8节分阶段并行安排。重构完成标准是使用更直接、责任更少且全部目标能力可用，不是文件更少或props更多。
