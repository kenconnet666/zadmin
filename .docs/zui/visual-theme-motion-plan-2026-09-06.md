# ZUI 视觉、主题与动画专项建设规划

日期：2026-09-06。执行关系：[完整能力总纲](./full-capability-roadmap-2026-09-06.md)的并行主线，覆盖当前全部 79 族/141 个公开组件及后续新增、删减、重构和组合。以下目标不代表已经实现或通过视觉验收。

## 1. 设计质量如何进入逐组件审计

每个家族同时评估功能/API、UI、主题、动画、可访问性和组合体验。视觉通过需要检查真实页面；仅有 CSS、token、variant 或动画参数不能算完成。处置结论同样包含保留增强、新增、删减、重命名、拆分合并、重新组合。

| 主线                 | 审计与建设内容                                                                        | 明确交付                                                |
| -------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| V1 比例与排版        | 控件高度、内边距、图标比例、文字基线、行高、边框、圆角、留白、紧凑/宽松密度           | 单控件与混合控件排布规范；五档几何和八档排版的实际样例  |
| V2 视觉层级与状态    | 主次操作、表面层级、选中与焦点、hover/active、disabled/readonly/loading、错误与空状态 | 每类状态的实际视觉表；状态不是仅改变透明度或色相        |
| V3 主题完整性        | 明暗模式、品牌与语义、前景背景配对、阴影/描边/遮罩、局部主题、图表/代码色板           | 主题级预览、局部覆盖用例、缺失 token/重复硬编码清单     |
| V4 样式与主题 API    | 全局语义→组件 token→parts/recipe→实例覆盖；defaults、responsive、密度和高对比         | 最终覆盖顺序与类型合同；不用覆盖私有 DOM 选择器才能定制 |
| V5 交互动效          | 微交互、出现/退出、展开折叠、定位变化、选区滑动、排序/重排、数值和进度                | 逐家族动效语义、触发时机、终态、可中断合同              |
| V6 复杂与异常组合    | 长中文/英文/URL、空值、大量数据、嵌套浮层、表单错误、加载、断网与重试                 | 实际复杂场景视觉与响应式例子，状态更新不引发布局跳动    |
| V7 Docs 与 Theme Lab | 所有视觉轴可比较、动画可重播/减速、源码可复制、桌面和窄屏阅读                         | 视觉工作台、组件状态画廊、主题修改即时预览与可复制配置  |
| V8 验收与删改        | 同时检查静态图、中间帧、终态、焦点与可访问树；删掉重复/无语义/造成负担的效果          | 每项有前后变化、处置原因、当前执行证据与迁移            |

## 2. 尺度、颜色与视觉语言

现有基线：控件 `xsmall/small/medium/large/xlarge` 高度 24/28/32/40/48；八档文字 11/12/14/16/20/24/32/40；五种状态色 `neutral/info/success/warning/danger`，品牌 `primary` 独立。它们是默认尺度，主题可以覆盖。文字、指示器、容器、面板和数据密度具有不同职责，不以同一像素表强行缩放。

- 五档审计包含内容高度、图标、间距、光学对齐、焦点环、点击区域及组合后的总高度。单纯改 `data-size` 或根高度不能证明整套比例正确。
- 大小与密度分离：size 负责控件尺度，density 负责列表/表格/布局的信息密度；不能两者叠加缩小两次。字号能独立表达内容层级，避免标题语义级别与视觉字级混为一谈。
- tone 表示状态/品牌，variant 表示视觉重量；保留已有 solid/outline/ghost 的职责，soft/subtle、plain 等候选按每类场景决定，统一同义名，避免所有组件无差别增加全部组合。
- 阴影、边框、圆角、遮罩、焦点环与表面层级共同塑造主题。霓虹类主题可以有局部强调，正文、表格和长时间操作区仍需稳定的阅读层级。
- 图标检查笔画、几何盒、光学大小、按钮内对齐、RTL 和装饰语义；去除零散文字图标或意义重复的图标。

主题的艺术方向应形成可检查的板式：工作台、密集表格、表单、阅读页、浮层和反馈区共用一套视觉语法。每个现有主题都做上述场景的整体检查；不能只换 primary 色就认为主题完整。

## 3. 主题与 ICSS 的目标能力

当前 Theme/ICSS 已有 token、recipes、parts 和运行时样式；本阶段审计其完整性和覆盖边界。以下为扩展设计方向，最终名称与现有接口对齐，不建立重复入口。

| 层次              | 目标能力                                                                                                  | 删减/重构重点                                                          |
| ----------------- | --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 原始尺度          | 色阶、space、size、type、radius、border、shadow、duration/easing、breakpoints                             | 合并无实际差异的别名，组件专用 token 不泄漏为通用 spacing 参数         |
| 语义 token        | canvas/surface/elevated、text/muted/inverse、border/focus/selection、status/on-status、overlay、drag/drop | 不让组件自行拼接不同透明度产生不一致状态；删掉重复但含义不清的 token   |
| 组件 token        | field、menu item、calendar cell、table row、dialog panel、chart series 等用途值与状态                     | 内部实现名与公开用途名分开；可组合成员共享明确的视觉 owner             |
| recipes/parts     | 视觉轴、compound 状态、命名 parts、局部覆盖、类型扩展                                                     | 合并重复样式；清理不可达组合、无消费者变量和需要私有 selector 的逃生口 |
| defaults 与上下文 | 全局/局部默认值、实例优先、density、locale、direction、motion preference                                  | defaults 不持有业务 value/open；避免父子上下文二次缩放和冲突           |
| ICSS              | 属性与关键词的 metadata/类型/序列化同步；CSS var/单位/响应式/容器查询/状态规则                            | 原生 CSS 已能表达的效果优先直接建模，删除重复运行时计算和无语义封装    |

覆盖顺序需要可预测且有实际消费者：基础主题→扩展/局部主题→组件默认值/recipe→显式实例选项→公开 parts/样式覆盖。具体继承与优先级必须由现有样式层叠事实验证；Svelte context 与 Portal 的实际 CSS 祖先分别检查。

对标 Chakra 的语义 token、text/layer/animation styles、recipes/slot recipes 与类型生成机制，采用适合 ZUI 的公开合同，不接入 React 样式运行时。[Chakra 主题架构](https://chakra-ui.com/docs/theming/overview)

## 4. 动画体系与逐类运动合同

动效用于说明状态变化、空间关系和操作反馈。默认方案优先清晰、克制、可中断；主题可提供更具表现力的配置。允许减弱或删除对理解没有帮助、造成抖动/延迟/视觉疲劳的效果。

建议形成全局与局部 motion policy：跟随系统、禁用、适度、强调等能力；最终命名应整合现有 reduced-motion 与 Presence 接口，不能留下两个互相冲突的开关。复用已有入场/退场生命周期，在出现真实消费者时补 placement、layout 或 drag 动画。

| 类别                               | 审计效果                                                   | 生命周期与异常要求                                                               |
| ---------------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Button/Checkbox/Switch/Rating      | hover/press、选中标记、滑块位移、loading 图标替换          | disabled 不假反馈；外部值变化与用户交互均达到同一终态；loading 前后宽度稳定      |
| Tabs/Segmented/Navigation          | indicator 平移、面板变化、溢出切换                         | 激活与焦点分别拥有；容器尺寸/字体改变后位置正确；按键快速重复不排队播放旧动画    |
| Accordion/Collapsible/Tree         | 高度展开、图标旋转、分支插入                               | 动态内容、快速反向、虚拟节点卸载；滚动锚定和焦点不丢失                           |
| Dialog/Drawer/Popover/Menu/Tooltip | fade/scale/slide、遮罩、方向/placement 与 transform origin | 初始 SSR-open、退出保留、反向打开、嵌套 Escape、动画中卸载，焦点锁与视觉状态一致 |
| Toast/Notification/ActionBar       | 堆叠重排、进退场、进度、更新                               | 关闭/过期/手动移除与 pause 一致；Promise 迟到结果不复活已销毁实例                |
| Slider/Range/DragDrop/Splitter     | thumb/track、drag preview、drop marker、邻项位移           | 用户直接拖动期间避免动画追赶指针；释放才进入合适回弹/归位；取消和键盘有同等反馈  |
| Calendar/Date/Time/Schedule        | 翻页、范围预览、事件移动/缩放、资源切换                    | 值域与时区先正确；焦点不随装饰动画丢失；拖动事件不可触发错误日期选择             |
| Progress/Meter/Statistic/Charts    | 数值、进度、数据更新、图例筛选与系列切换                   | 区分真实值和绘制插值；频繁数据合并更新；禁用运动仍能看清最终数据                 |
| Skeleton/Loading/Upload            | shimmer/pulse/spin、队列和进度更新                         | 不靠动画才可辨识忙碌；不可见或卸载时停止；失败/取消及时结束                      |
| Image/Carousel/Lightbox/Editor     | 视图切换、缩放、工具栏/菜单、插入提示                      | 保持滚动/selection/caret；触摸手势与页面滚动不冲突；编辑区不做破坏阅读的整体移动 |

每项记录 trigger、进入/退出 duration、easing、delay、origin/distance、终态、可否中断、reduced fallback、owner 和 cleanup。时长不能用统一常数机械覆盖所有效果；延迟显示 Tooltip 与其进入动画分开。

系统减少动态效果偏好需要即时生效。取消运动后直接达到有意义的终态，不能留下半透明、不可点或存在不可见焦点的元素；同时检查缩放、位移、滚动和视差，不能只停一个 CSS animation。[MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)、[W3C 交互动画说明](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)

## 6. Docs 和视觉工作台

- Theme Lab 展开为真实组件工作台：主题、模式、五档大小、八档文字、tone/variant、density、locale/RTL、视口与 motion policy 可组合；预览配置可以复制。
- 组件状态画廊包含普通、hover、focus、active、选中、disabled、readonly、loading、invalid、empty/error 等适用状态，演示真实交互与静态排列各有用途。
- 动画可重播、减速、切换 reduced 并观察中间帧；检查快速重复操作、退出再打开、卸载和异步迟到，记录效果归属。
- Docs 正文/API/源码自然换行，宽屏和窄屏重新排版；表格等确有二维数据需求时保留明确的局部滚动，页面不出现横向滚动条。复制按钮保持源码切换按钮左侧，成功反馈不移动布局。
- 对照页展示同一场景在多主题下的整体布局，形成可检查的设计修改记录；图片用于视觉记录，真实 DOM 和计算样式用于证明交互与几何。

## 7. 每批执行与验收

V1–V4 随总纲 W1 先确立统一接口与设计规则；V5 与对应组件实际实现同步；V6–V8 横贯所有波次。首批选择布局工作台、输入/选择表单、嵌套浮层三个不同场景，验证基础规则再推广；当前组件与新增组件都进入同一标准。

1. 填写家族处置表：现状问题、参考能力、保留/删增/拆并/重组、最终 API 和视觉责任。
2. 落实共用 token/recipe/交互原语和实际消费者，清理被替代的重复逻辑。
3. 完成常规、复杂、异常及窄屏 Demo，同时更新 API/迁移/源码。
4. 本地 WebStorm 检查受影响文件，通过浏览器插件检查真实几何、视觉与交互；完整浏览器矩阵交 CI。
5. 记录源码 SHA、主题/状态/视口、静态图/动态帧/断言和实际结果。已写合同、已执行、已接受分别统计。

视觉验收使用风险矩阵而不是无意义全排列：公共尺度做完整覆盖，各家族保留实际消费者验证；关键复合状态、明暗/局部主题、390px/桌面、RTL、高对比与减少运动有适用证据。未执行项明确待验证。文件体积只提示，布局稳定性、交互响应与资源清理仍需按实际场景验证。
