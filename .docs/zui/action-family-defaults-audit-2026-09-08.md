# Action family defaults audit（2026-09-08）

## 范围与证据边界

本次只审阅 Button、CopyButton、Toolbar、Menubar、ToggleGroup、Segmented 六个实际消费者及其共同 defaults/runtime 源码；不是全库审计。以下优先级表和缺口保存 P03 修改前的源码审阅基线，行号也是该基线定位；当前修复与实际执行结果见末尾“本次落地记录”。不能把历史缺口当作仍未修复，也不把测试文件存在等同于运行通过。

共同规则源是 [`COMPONENT_RULES`](../../ui/zui/src/runtime/foundation/component-defaults.ts:55)：`button`、`copyButton`、`menubar`、`segmented`、`toggleGroup`、`toolbar` 的可配置字段分别在 66–68、129、140、147–153 行；其中 `copyButton` 复用 `actionButtonRules`，`toggleGroup` 复用 `buttonRules`。最终 density fallback 由 [`resolveControlSize`](../../ui/zui/src/runtime/foundation/control-size.ts:68) 完成，`undefined` 映射到 Provider density（compact→small、comfortable→medium、spacious→large）。

## 可确认的不一致、重复与合理复用

### 已确认的不一致

1. `ZToggleGroup` 的源码 size 链包含 `delegated ? toolbar!.size : undefined`（[`ZToggleGroup.svelte:310-317`](../../ui/zui/src/components/input/ZToggleGroup.svelte:310)），但同文件 metadata 的默认值只写 `Field → componentDefaults.toggleGroup → button → Provider density`（[`ZToggleGroup.svelte:75-78`](../../ui/zui/src/components/input/ZToggleGroup.svelte:75)）。这不是推测：调用顺序明确少了 Toolbar 层。
2. `ZCopyButton` 的普通 tone fallback 是 `neutral`，不是 `button.tone`/`primary`；这是由状态 tone（copied→success、failed→danger）和 250–255 行的显式 neutral 分支共同确认的行为。它与 Button 不同，但目前更像 CopyButton 的语义设计，而不是应立即改成一致的缺陷。
3. `ZToggleGroup` 的 variant 本地最终 fallback 是 `outline`（321–323），`ZButton` 的基线是 `solid`（[`ZButton.svelte:405-407`](../../ui/zui/src/components/gene/ZButton.svelte:405)）。这是 ToggleGroup pressed 控件的独立视觉默认，不能只按“共享 Button”推导成错误。

### 已确认的重复与合理复用

- 六个消费者都把最终尺寸交给 [`resolveControlSize`](../../ui/zui/src/runtime/foundation/control-size.ts:68)，这是已经存在且合理的最小公共部分；不应再在每个 family 复制 density→control-size 映射。
- `COMPONENT_RULES` 通过 `buttonRules` / `actionButtonRules` 复用可接受字段与枚举（[`component-defaults.ts:35-53`](../../ui/zui/src/runtime/foundation/component-defaults.ts:35)）；这是验证规则复用，不等于每个消费者必须采用相同的优先级。
- Toolbar 与 Menubar 都使用 `family.size → button.size → density`，但只有 Toolbar 需要向 Button/Input/ToggleGroup 子树传播已解析尺寸；这两段表达式重复的是优先级形状，职责并不重复。
- ToggleGroup 和 Segmented 都支持 Field size 优先，但 ToggleGroup 还需 Toolbar delegation，而 Segmented 通过 Toolbar 的 Provider `input.size` 间接继承；当前差异有明确上下文原因，不建议抽成一个无参数的“所有 action size resolver”。

## 两个以上消费者可共享的最小部分

当前最小公共部分已经存在：`resolveControlSize(size, density)` 被 Button、CopyButton、Toolbar、Menubar、ToggleGroup、Segmented 共同消费，负责唯一的 density 映射；规则侧的 `buttonRules` 也被 `button`、多个 action/family defaults 复用。

若后续确需减少表达式重复，安全边界只能是一个保留调用方上下文顺序的纯 helper，例如接收“已按消费者语义排好优先级的候选 size”后调用 `resolveControlSize`。不建议把 Field、Toolbar delegation、family defaults、base Button defaults 合并进一个隐式 resolver：六者的优先级并不相同，且 Toolbar 有 Provider 传播副作用、CopyButton 有状态 tone 覆盖。

## 建议的 2–3 个回归场景

这些是下一步可执行的最小场景建议，不是本次执行证据；相关既有测试资产包括 [`toolbar-toggle-group.browser.spec.ts`](../../ui/zui/tests/toolbar-toggle-group.browser.spec.ts)、[`toggle-group-production.browser.spec.ts`](../../ui/zui/tests/toggle-group-production.browser.spec.ts)、[`menubar-production.browser.spec.ts`](../../ui/zui/tests/menubar-production.browser.spec.ts)、[`segmented-focus-ownership.browser.spec.ts`](../../ui/zui/tests/segmented-focus-ownership.browser.spec.ts)、[`copy-button-production.browser.spec.ts`](../../ui/zui/tests/copy-button-production.browser.spec.ts)。

1. **Toolbar → descendants 尺寸传播**：同时设置 Provider `button.size`、`input.size`、Toolbar `size`、ToggleGroup 显式 size 和 Segmented Field size，分别断言 `data-size`；覆盖 Toolbar 532–537 的三轴注入和 ToggleGroup 312–317 的 delegation，不把 Segmented 的间接继承误测成直接 context。
2. **Button/CopyButton fallback 分叉**：只设置 `button.tone='primary'`，不设置 CopyButton tone，断言普通 CopyButton 为 neutral；再验证 copied/failed 状态分别为 success/danger，同时 Button 仍为 primary。该场景保护 248–255 的有意差异和内部 Button fallback。
3. **ToggleGroup metadata 与运行时链**：在 Field + Toolbar 嵌套下不设置 ToggleGroup size，断言 Toolbar size 优先于 `componentDefaults.toggleGroup.size`；同一场景核对文档/metadata 对实际链的描述，防止回归时删除 delegated Toolbar 层或再次漏写说明。

## 本次落地记录

已将唯一确认的 metadata 不一致修正：[`ZToggleGroup.svelte:75-78`](../../ui/zui/src/components/input/ZToggleGroup.svelte:75) 现在明确记录 `Field → delegated Toolbar → componentDefaults.toggleGroup → button → Provider density`，并保留实例显式 `size` 优先语义；解析实现未改动。

新增 [`ActionDefaultsFixture.svelte`](../../ui/zui/tests/ActionDefaultsFixture.svelte) 与 [`action-defaults.browser.spec.ts`](../../ui/zui/tests/action-defaults.browser.spec.ts)，覆盖 Provider 的 `button/input/family` defaults、Toolbar 尺寸传播、显式子尺寸及 Field 优先级。普通 Button 与 Toolbar 内 Button 使用非默认 `danger` tone，CopyButton 仍为 `neutral`；非默认值可识别真实继承，避免 `primary` 与内建 fallback 相同而漏检。

Segmented 保留三个独立场景：无 `segmented.size` 时继承 Toolbar 注入的 `input.size`；Toolbar 内更近的 Provider 配置 medium 时专属值优先；Toolbar 外层 Provider 已配置 small 时，该专属值仍胜过 Toolbar 的 xlarge 基础 fallback。这是现有 Provider 合并和专属优先语义，不能宣称所有表单控件都无条件继承 Toolbar.size。是否需要局部 `ControlSizeScope` 留待后续 G1 设计，不在本批扩展运行时。

断言读取真实 `data-size`、item 尺寸、computed height/font-size、Field 内唯一 role owner 与 tone；Field xlarge 验证实际 48px/16px 几何，不触发 clipboard 权限。尺寸/组合两项 Chromium 已通过；最终非默认 tone 加强后的执行结果与精确 SHA 以主执行计划 P03 记录为准，不代表全库审计完成。
