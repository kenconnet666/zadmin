# 企业级组件能力对标与建设矩阵

日期：2026-09-06。范围：ZUI 的通用/排版、布局、导航、数据展示、反馈、浮层、图表、日程及企业高阶组合；复杂输入和统一基础设施由同一主任务的独立矩阵补全。

**用户最新方向是大范围新增与全面能力对标。本文替代旧规划“仅优先 Breadcrumb、其余小范围候选”路线，也覆盖旧文档对 Steps、Toolbar、QRCode、RangeSlider、RichText 等的历史排除。** 当前正确性修复继续完成，但不能用“等全部完美稳定”或“暂无现成消费者”把已经明确要求的企业能力长期冻结。本文件与[完整能力总纲](./full-capability-roadmap-2026-09-06.md)配套；不修改生产源码、不执行测试/CI、不提交。

## 1. 对标口径与证据

- 本次在线读取的 [Ant Design 官方目录](https://ant.design/components/overview/) 显示 **6.6.2**，七类 core 共 **73 个目录条目**，另列 Pro Components 等扩展。
- [Mantine Core 官方目录](https://mantine.dev/core/package/) 显示 **9.6.0**，本次目录清点 **118 个 core 条目**；[扩展目录](https://mantine.dev/charts/getting-started/)另含 Dates、22种 Charts、Schedule、Lightbox、Notifications、Spotlight、Carousel、Dropzone、NavigationProgress、Modals、RichText。
- Context7 已 resolve 并查询 Ant Design 与 Mantine 的 Table/Charts/通知服务 API；其版本索引比在线目录滞后，因此新增目录和具体API以实际官方页为准。ProTable补读[官方仓库当前类型源码](https://github.com/ant-design/pro-components/blob/master/src/table/typing.ts)，不把第三方 Mantine DataTable/Mantine React Table 当作 Mantine Core。
- ZUI现有规模以[catalog](../../apps/docs/src/framework/catalog-manifest.generated.ts)的 **79族/141个公开组件**为基线。本文共登记 **123个能力检查点**，不是“123个全新组件”，也不是按同名计算出的覆盖率。
- `已有核心`：当前源码覆盖基础职责，仍需验证完整目标维度；`部分`：有对应组件但缺主要API/交互/视觉能力；`缺失`：没有公共能力；`需重构`：能力仅存在于Docs或私有runtime，需要形成稳定公共边界。
- **同名不代表能力完整**：ZMenu命令菜单不等于网站NavigationMenu；ZCalendar日期选择不等于Schedule；ZCarousel不等于Scroller/Lightbox；ZVirtualList不等于完整DataTable/Listy；ZStatistic/Progress不等于Chart；ZInputGroup不等于多业务控件Space.Compact。

矩阵中的“目标API”是ZUI的拟议能力维度，不是复制React库参数，也不是已经实现的承诺。核心DOM、状态、ARIA、Collection/Form/Layer由ZUI拥有；图表、日程循环计算、编辑器、二维码可评估成熟非React领域引擎并提供可选入口，不因算法复杂取消能力。

所有动效须提供清晰的主题消费与关闭路径：duration/easing、变换幅度/方向、层级/遮罩、visibility和reduced motion是验收维度，不是只加一个animated布尔值。高对比主题与业务颜色也要独立：例如Chart类目颜色、Calendar事件颜色、ColorPicker的实际颜色不能被五种状态色覆盖。

## 12. 目录闭合、迁移与验收要求

- Ant目录中List旧形态与Listy新形态分别登记；Masonry、BorderBeam、QRCode、Watermark、FloatButton/BackTop、App/ConfigProvider和Pro系列都已纳入。Mantine core的布局/按钮/导航/反馈/浮层/数据/排版/misc各类已在G/L/N/D/O域对应；input/combobox类别交输入矩阵，但该类不能因交接而从总纲消失。
- Mantine Extensions中的CodeHighlight/Notifications/Spotlight/Carousel/Lightbox/NavigationProgress/Modals在本矩阵；Dropzone/RichText/Dates在输入专题；Charts与Schedule在C/S域。每个页面/组件的Props、交互、UI、Theme、Motion、组合与边界都要进入正式验收，目录条目只是入口。
- 新建可复用组件与重构已有组件都属于交付：可复用同一个runtime/recipe，但必须提供用户可用的能力，不以“自行组合ZBox/ZStack即可”关闭缺口。
- 现有API应分可兼容新增与破坏性调整；如Table单sort→多sort、Tabs工作区关闭、NavigationMenu与命令Menu分工、compact多owner、Chart/Pro schema应给迁移表、类型负例和真实消费迁移。旧文档限制被新指令覆盖，不留相互矛盾的路线。
- 保留来源、baseline SHA与“计划/实现/执行/接受”四种证据。本文是研究规划，没有运行测试/CI，没有把metadata stable或已有名字当成功证明。
- 验收必须包括实际UI/Theme/Motion：多主题/高对比、五档/八字级、LTR/RTL、窄屏/桌面、hover/focus/active/disabled/loading/error/selected、进入/退出/中断/reduced、真实数据/键盘/触摸、SSR/CSP/HMR/Portal/owner Window。对数据表/图表允许有明确owner的横向阅读，不能全页溢出或裁掉必要内容。
