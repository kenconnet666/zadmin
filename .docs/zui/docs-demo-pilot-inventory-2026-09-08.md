# ZUI Docs Demo Pilot Inventory（2026-09-08）

## 范围与判定方式

本清单只审阅当前工作树中的 `doc.ts` 与其 `demos` 引用的 `.svelte` 源码，范围为 Button、Form、DateTimeField、DateTimePicker、DateTimeRangePicker、Sortable、DataTable。判定以源码实际渲染和事件处理为准；`covers` 只作为索引，不作为“内容重复”或“能力已覆盖”的证据。

表中“复制性”关注把 demo 单独复制到一个最小 Svelte 页面时，是否能从源码看出辅助类型、数据、schema、raw source、依赖和 owner。测试引用是已有组件运行时/浏览器/SSR 测试的相关证据入口，不等同于该 demo 已被自动化点击验收。

动作含义：

- **保留**：当前教学目的独立，源码与描述基本一致。
- **合并**：两个 demo 的可观察教学目标高度重叠，合并后仍应保留更强的边界证据。
- **重写**：ID 可以保留，但源码实际没有兑现描述，或复制后缺少关键 owner/依赖/边界。
- **新增**：当前集合没有真实演示目标，需补充独立 demo 与可执行验收。

## 复制性与缺口汇总

| 维度                  | 当前证据                                                                                                                                                                                                    | 结论                                                                                                         |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 辅助文件与 raw source | 指定 demo 都在各自 `doc.ts` 中显式 import demo 组件和 `?raw` source；Form/日期/Sortable/DataTable 的类型、schema、rows 多数定义在 demo 内。                                                                 | 具备复制基础；`form-nested-list`、DataTable rich/virtual、日期 family 复制成本较高，需保留全部辅助 imports。 |
| 受控 owner            | Button async、日期 picker value、Sortable controlled、DataTable selection/server、Form controller/model 明确由外部变量或 controller 持有。                                                                  | 覆盖较强，但各家族 owner 语义不同，不能按 `controlled` 合并。                                                |
| 外部清空              | Button 无外部 value；DateTimeField/Picker 部分使用 `external-clear` cover，Form/date model 有 clearable 或 controller 写入，但不是所有 demo 有独立清空按钮。                                                | 需要逐 demo 浏览器确认；不能仅按 cover 记录已覆盖。                                                          |
| reset                 | Button form、Form 多个 model/list/controller demo、`date-time-picker-inline` 的“恢复预约”、日期 picker/range family 有原生 reset；value/constraints/presets、range basic 和 DataTable demo 通常没有 reset。 | reset 证据存在但局部，不是家族全覆盖。                                                                       |
| 异步拒绝/取消         | Form schema 有 Promise reject；Sortable controlled 有 AbortSignal + 模拟异步确认；Button async 没有 reject；DataTable async states 没有真实 promise。                                                       | 下一批应优先补 Button reject 或 DataTable 外部 async owner，而不是复制现有 loading 表面。                    |

## 最小下一批建议（2–3 项）

建议下一批只做以下 3 项，按“最少新增、最大边界收益”排序：

1. **重写 `data-table-async-states`（优先）**：保留现有 loading/error/empty 表面，但把状态由可取消的外部 async owner 驱动，至少有旧 rows 保留、请求拒绝、重试、过期结果不覆盖当前状态；保留现有 `AsyncStatesDemo.svelte` 的可视表面，避免重复造 DataTable 结构。对应 `data-table.browser.spec.ts`、`data-query.spec.ts`。
2. **重写 `button-async`**：加入显式成功/拒绝分支和“拒绝后可再次操作”结果，继续保留 timer cleanup；这样与 `button-states` 的静态 loading 分工明确，补齐 Button 当前缺少的异步拒绝证据。对应按钮生产浏览器合同与组件的 loading/aria-busy 测试。
3. **为日期 picker 家族补一个最小外部清空/RTL/reduced 验收 demo 或扩展现有 `date-time-picker-value`**：不要复制 `Family`/`Constraints`；在已有 controlled owner 上增加 `value=null`、reset 后 draft、逻辑方向键和 reduced motion 的可观察输出。若一次增加 3 个轴会让 demo 失去单一教学目的，则拆成浏览器验收 fixture，不计入公开 demo 数量。

这三项完成前，不建议合并现有日期家族 demo，也不建议删除 `data-table-boundaries`；后者应先决定是保留为边界说明还是迁移到 guide prose。
