## 3. 已完成的修复

### 3.1 依赖安装与 CLI

- 用户级 npm registry 与 pnpm effective registry 均已切换到 `https://registry.npmjs.org/`。
- 官方 registry HTTP 探测返回 200。
- `@zadmin/webview` 与 `@zadmin/miniapp` 改用始终随包存在的稳定 bin shim，避免 clean install 时出现 `Failed to create bin`。
- 前一个远端 clean install 已证明 registry/install/bin 警告消失。

### 3.2 Form reset 与集合 teardown

- 所有普通 reset 测试统一通过 owner-window timer + Svelte tick 等待原生 reset 生命周期。
- reset 诊断 `<output>` 已移出原生 reset owner，避免浏览器把诊断节点自身当作表单控件重置。
- 新增 AST 门禁，禁止测试 fixture 再把诊断 `<output>` 放入 `<form>` / `ZForm`。
- `ZRadioGroup` 与 `ZSegmented` 的延迟 nearest-focus recovery 在 owner teardown 后不再读取失效 derived state。
- teardown 回归测试改用 `render()` 返回的局部 unmount；全局 browser cleanup 仍只有 `browser.setup.ts` 一个 owner。

### 3.3 Callable API 文档合同

- 新增并公开 `ZuiCallableMetadata` / `ZuiCallableParameterMetadata`。
- structured members、opaque boundary、callable 三种 API shape 在类型层互斥。
- callable 生成器严格校验参数数量、顺序、名称、type、required/optional、rest，并拒绝未实现的 `returns` metadata。
- 支持直接函数、nullable wrapper、local/imported alias、泛型绑定和单 call-signature interface；多 callable union、非 callable union、零/多 call-signature interface 均 fail closed。
- callable payload 的 public facts 支持方法签名、泛型遮蔽与嵌套成员；数组参数只保留参数边界，不伪造数组元素成员路径。
- `ZForm.onValidSubmit` / `onInvalidSubmit`、`ZFileUpload.transport` / `onReject` 已拥有参数级 API 文档。
- Docs API 表递归展示 callback parameter/payload，并标识 variadic 参数。

### 3.4 Docs 计数与运行态

- 首页不再把 79 个组件族路由误写成公开组件总数，也不再保留已经失效的 experimental 文案。
- catalog 生成器从每个 `defineComponentDoc(..., { members })` 的 AST 自动计算公开组件数，并与 141 个 metadata exports 做一致性校验。
- WebStorm 中存在 `dev` 运行配置；`http://127.0.0.1:5174/` 经 IDE 集成终端返回 200。
- 浏览器实际查看 Form API 页面，已确认 callback 参数与 `data/formData/originalEvent` 嵌套字段正确呈现，浏览器 console 无 error/warn。

### 3.5 Desktop / WebView2 证据

- 已有 Button、Form、choice controls、Select、Dialog、Tabs、Accordion、Popover、Tooltip 等动态合同。
- 本轮新增 11 个 primitive：`ZHeading`、`ZCode`、`ZIcon`、`ZKbd`、`ZLink`、`ZSeparator`、`ZVisuallyHidden`、`ZAspectRatio`、`ZContainer`、`ZAlert`、`ZSpinner`。
- Windows C# host 从真实 DOM、computed style、geometry、event cancellation、state delta、ARIA 和 Web Animations API 采集证据。
- `ZLink` 使用单次操作 delta，重复执行报告不会因累计计数误报。
- `ZSpinner` reduced-motion 同时验证状态标记和 indicator `getAnimations().length === 0`。
- C# 使用强类型 `DesktopPrimitiveInteractionEvidence`，关键字段在写报告前 fail fast。

### 3.6 Release handoff 与生产工作流

- release handoff 已绑定同一 CI revision 下的 support matrix bytes、SHA-256 和安全固定路径。
- 新增手动触发的 `Production Release` 工作流，分为：
  1. read-only preflight；
  2. `production` environment 下的 npm publish/tag/GitHub Release；
  3. `github-pages` environment 下的版本化 Docs 部署。
- downstream jobs 只使用 preflight 验证后的 SHA/run id/version/tag。
- 高权限 publish/deploy jobs 不执行 workspace install/postinstall；只使用 Node 24、npm >= 11.5.1 和内置模块验证脚本。
- npm probe 只有 404 表示版本不存在；网络、TLS、5xx、JSON、package/version 或 SHA-512 integrity 异常均失败。
- tag 复用校验 annotated tag 的 peeled commit；`ls-remote` 明确区分存在、不存在和基础设施错误。
- GitHub Release probe 只有 REST 404 表示不存在；已存在 release 必须绑定 exact tag、stable flags、恰好三个 assets，以及与本地文件一致的 size/SHA-256 digest。
- 本轮没有执行 npm publish、push tag、创建 GitHub Release 或部署 Pages。
